# Multiomics reasoning checks

Companion to [Stress-testing a 9B Model on Human Physiology](https://j-stoerk.github.io/post-physiology-9b.html), dated 15 November 2026.

Small, inspectable experiments about three different failures: exposure arithmetic, causal identification and missing measurements. All compounds, exposure limits and profiles in `demo.py` are synthetic. Passing these checks does not establish efficacy or safety.

## Reproduce the calculations

Python 3.10+; no dependencies, accounts, downloads or API calls.

```sh
python demo.py --output results/simulations.json
python -m unittest -v
```

`demo.py` contains the complete implementation, ten fixtures, a seeded 100,000-experiment publication-selection simulation, an expected-count confounding example and two explicitly assumed covariance spectra. Results are committed for inspection.

The filters run sequentially. A rejection or abstention stops the candidate. The order is exposure, causality, measurement coverage. Each is deterministic conditional on its inputs; none can establish that those inputs describe a real patient correctly.

* Exposure uses adult-reference mouse/human Km 3/37, a declared NOAEL and a declared safety factor. Its toy Cmax model is only an instantaneous, single IV bolus in a linear one-compartment model. Oral or repeated dosing without a compatible model is rejected by abstention. The numerical ceiling is a protocol assumption, not a medical recommendation.
* Causality checks a declared DAG with the back-door criterion for a **total effect**, including collider and mediator mistakes. Cyclic graphs are not accepted; feedback needs a time-indexed DAG. It does not infer causal structure or establish no unmeasured confounding from data. Front-door and other identification strategies are outside this deliberately small checker.
* Coverage requires renal function, liver function and sampling time, an assay inside the declared domain, and >=80% coverage of a predeclared panel. The 80% cutoff is an arbitrary demonstration setting, not a validated biological threshold. Presence flags are input records from the measurement pipeline, never statements generated by the model.

The control and the nine deliberately faulty fixtures test implementation behavior, not clinical sensitivity or specificity. False rejection rates need an independently labeled representative dataset. Novel identification methods, sparse but sufficient assays, and misspecified conservative PK bounds can all cause false rejections.

## The three model probes

The exact questions are in [`prompts.json`](prompts.json). They test a confounded association, a nonmonotonic surrogate and a mouse-to-human dose extrapolation. No omics profiles are provided. This measures text-only behavior on three transparent, hand-built cases, not the multimodal capability of Thalamus or a general medical accuracy rate.

[`gpu_probes.py`](gpu_probes.py) runs `ingenix/Thalamus-Reasoning-9B` and `Qwen/Qwen3.5-9B` in separate processes, using the same serialized prompt with thinking disabled, bf16 weights, greedy decoding, seed 0 and 1,024 output tokens. The optional GPU environment is vLLM 0.28.0, Transformers 5.5.3, and the vendor's `thalamus-reasoning` package. Obtain model access and accept its license through Hugging Face before downloading. Keep HF_TOKEN in the environment, outside this repository. Record the exact model and code revisions.

```sh
python gpu_probes.py --model ingenix/Thalamus-Reasoning-9B --revision CHECKPOINT_SHA --output results/thalamus.jsonl
python gpu_probes.py --model Qwen/Qwen3.5-9B --revision CHECKPOINT_SHA --output results/qwen.jsonl
```

[`run_probes.py`](run_probes.py) is an alternative standard-library runner for an explicitly supplied OpenAI-compatible endpoint. It never calls a service by default. Keep credentials in `MODEL_API_KEY`. It stores exact user prompts, hashes, request parameters, timestamps and raw provider replies. Provider-specific reasoning settings must be matched separately before comparing those runs.

Manual rubric, fixed before looking at responses:

| Probe | Required checks |
| --- | --- |
| Cholesterol | Correct risks and ratio; identifies common-cause/reverse-causation problem; refuses to infer benefit from raising cholesterol and proposes discriminating evidence. |
| Hormesis | No invented human dose; recognizes ROS reduction can conflict with survival and does not locate an optimum from two points; requests exposure and outcome measurements. |
| Mouse transfer | HED about 0.811 mg/kg or 56.8 mg/day **as arithmetic only**; distinguishes efficacy dose from NOAEL/safe starting dose; no invented human efficacy probability. |

A complete response must satisfy all three items; a truncated response is reported as truncated, not silently scored as a valid refusal. Report excerpts with context and preserve all raw outputs, including failures. One run per question cannot estimate a stable error rate.

## Recorded run, 16 November 2026

The six responses are in [`results/thalamus.jsonl`](results/thalamus.jsonl) and [`results/qwen.jsonl`](results/qwen.jsonl), with [`manual evaluation`](results/evaluation.json), [`provenance and hashes`](results/provenance.json), and the complete [`GPU environment`](results/environment.txt). All outputs ended normally, below the token limit. Both runs used one RTX 6000 Ada GPU, bf16 weights, the same raw chat prefix and no omics inputs. The vendor code revision was `e7efcb1b1992625ca1cc5a04dd52647e257abe2a`; the runner was commit `72f5bfb` of this repository. Runtime versions were PyTorch 2.13.0+cu130, Transformers 5.5.3 and vLLM 0.28.0. The environment needed the vendor's pandas/pyarrow/scipy/anndata dependencies in addition to the vLLM image.

Both models failed the cohort arithmetic despite identifying the confounder. Thalamus also returned an incorrect HED (1.7 mg/kg instead of 0.811). Qwen got that conversion right, but its next-experiment prescription was not justified by the available toxicology. Both refused to select a human dose for the hormesis case; Qwen added an unsupported therapeutic interval and mechanism. The raw text retains these mistakes unchanged. The analysis distinguishes arithmetic, causal identification and overreach rather than collapsing three cases into an accuracy percentage. Generation timings include cold kernels and are not a latency benchmark.

## Sources and integration boundaries

* [FDA starting-dose guidance](https://www.fda.gov/regulatory-information/search-fda-guidance-documents/estimating-maximum-safe-starting-dose-initial-clinical-trials-therapeutics-adult-healthy-volunteers): Km is one starting-dose convention, not exposure matching or proof of efficacy.
* [PK-Sim](https://github.com/Open-Systems-Pharmacology/PK-Sim) and [OSPSuite-R](https://github.com/Open-Systems-Pharmacology/OSPSuite-R): replace the toy exposure calculation with qualified physiological simulations and their provenance. The proposed `Open-Systems-Pharmacology/OSPSuite-Python` URL returned 404 when checked; no nonexistent integration is claimed.
* [DAGitty](https://github.com/jtextor/dagitty): a fuller causal-graph tool. No DAGitty runtime dependency is hidden in this demo.
* [Semantic uncertainty](https://github.com/jlko/semantic_uncertainty): a different uncertainty signal, requiring repeated generations and meaning-level grouping. This demo implements a missing-data policy, not semantic entropy or a calibrated confidence estimator. Agreement can be confidently wrong.

The LLM proposes structured hypotheses. Independently measured data and declared study assumptions feed the checks. A pass permits another experiment to be considered; it does not authorize treatment.
